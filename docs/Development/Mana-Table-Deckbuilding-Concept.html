Research, scope & what this concept proposes＋

Familiar tools, connected to play

  • Moxfield’s first-party feature wiki documents role tags, separate boards, history, curves, and sample hands. Last edited in 2020; a baseline, not a current exhaustive audit.
  • Archidekt’s stats redesign connects charts to the cards behind them. Its team added a condensed view after feedback: keep the overview readable and detail close to the decision.
  • ManaBox’s deck guide documents mana production, cost distribution, curves, and draw simulation.
  • Archidekt's official API discussion describes public read access. Public deck JSON was checked during this research; authenticated writes and a stable integration contract remain unverified.
  • Wizards: Five Trials of Playtesting supports purposeful tests and cautions against treating small samples as precise matchup rates.
  • EDHREC’s guide explains list-based recommendations. Inclusion data is a source of ideas, not measured performance for this player’s deck.
  • Archidekt playtester guide explicitly describes a manual play area without rules enforcement. Mana Table can connect the builder to its actual game engine.

Research supports a workflow hypothesis, not a claim that all Magic players build the same way.

Exists today / needs native work

Existing foundations: native deck editing and construction feedback; the shared rules engine; Commander play with human and AI seats. Backend insights already use heuristic roles and a small curated suggestion pool, but the native client does not consume that contract.

Proposed here: Archidekt source linking with reviewed incoming changes, preservation of categories / excluded cards / original printing metadata, durable named revisions, multi-role overrides in native UI, Considering separate from sideboard, always-visible composition during invalid drafts, configurable practice setup, session evidence, in-game notes, and a direct return to the same deck.

The current editor’s revision number is a transient concurrency counter, not durable history. Current solo launch uses three AI opponents; two- and six-player configuration here is a design proposal. Current simple practice-hand API has no persisted test history, seed, or format-specific mulligan procedure. Upstream Forge can read an Archidekt URL, but the native Mana import path accepts text and does not preserve source categories and excluded boards; lossless source linking needs new work.

No HTML control launches the engine, writes a deck, or produces measured analytics. The 100-card example is represented by summary counts and a labeled card-list sample. Role counts are overlapping. Commander is excluded from library role and curve figures.

Hypothesis to validate

Players can make a more deliberate deck change when a small set of contextual insights leads directly to a focused test and back to a reversible edit.

Observe three tasks: cut 110 cards to 100 while keeping two pet cards; investigate why a deck misses its own fun/theme plan through tests and notes; reconcile simultaneous Archidekt and local edits, then identify the exact version already tested. Check whether they can distinguish a source count from probability, an observed event from its cause, and revision 7 evidence from an untested revision 8.

Success means players can explain their change and recover the previous deck without hunting for a guide or a “Review deck” button.
